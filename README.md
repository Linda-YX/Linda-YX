# finances. · 个人财务工作台

按照 `docs/PERSONAL_FINANCE_MVP_SPEC.md` 实现，沿用提供的 HTML 原型的布局、配色和中文四页导航。第一版采用已确认的**浏览器本地存储**方案，使用 React、TypeScript 和 Vite。

## 启动

需要 Node.js 22.13+（本环境已验证 Node.js 24）。

```sh
npm ci
npm run dev
```

开发服务器默认使用 5173 端口。构建及预览：

```sh
npm run build
npm run preview
```

初次打开会载入**虚构示例数据**，净资产为 $72,640 CAD，与参考原型一致。真实使用前点击顶部“清空示例，开始使用”，然后添加自己的账户。未录入余额的账户不计入合计。

## 单文件交互预览

```sh
npm run build:standalone
```

生成 `standalone/finances-preview.html`，可下载后用现代浏览器打开，四个页面可直接点击。样式、JavaScript、CSV 模板和 PDF 提取 Worker 均内嵌，不需要启动 localhost 服务或发布云环境。若浏览器阻止本地文件脚本或存储，请使用上面的开发服务器方式。

这个文件仍然采用浏览器本地存储。文件预览与开发服务器不是同一个来源，因此两者的数据不会自动共享；请勿依赖本地 HTML 文件模式长期保存财务数据。

当前 Codex 云环境 onboarding 界面未提供可打开的网页预览或端口转发工具。保存/发布云环境只保存开发环境配置和快照，不等于发布网站，也不会自动产生公开网站地址。

## 已实现

- **总览**：净资产、资产/负债分组、已确认快照历史、跨平台合并的前三大持仓与季度/年度金额变化。
- **账户**：现金、投资、信用卡、Federal / Alberta / Quebec 学生贷款及其他贷款；添加账户、手动余额、来源/日期与更正历史。
- **投资组合**：账户金额变化、行业分布、地区环形图、未知分类、按平台和类别筛选的持仓、分类来源及汇率说明。
- **报告导入**：CSV 列匹配、文本 PDF 提取、逐笔手动输入；确认账户和日期、编辑候选行、核对来源页/行，勾选确认后才更新财务数据。
- 本地持久化、JSON 导出、完整删除、SHA-256 文件重复提示、同日替换或保留两份，以及审计记录。
- 桌面与手机布局、键盘操作、原生焦点约束对话框、保存失败提示和损坏数据保护。

## 数据规则

- 负债保存为正数欠款，计算净资产时扣除。
- 投资账户总额只计一次；同日有总额时优先使用总额，与持仓及现金核对差异。无总额时用已确认持仓加账户现金；较新的持仓快照可取代过期总额。
- 每次确认形成快照。替换只标记旧记录已被替代，旧值和来源保留在历史/导出中；保留同日两份时采用最新确认记录，不重复累加。
- 图表只连接保存过的快照日期，按日期间隔绘制；某日的账户总额取该日及之前最近的记录，显示缺失、不同日期及超过 30 天未更新的情况。
- 季度/年度基准取报告日期减 3/12 个月当日或之前最近的快照；缺少基准或基准为零时，相应变化率显示“—”。金额变化包含现金流和买卖，**不是投资回报率**。
- 原币金额一直保留。外币只有在汇率、日期和来源完整时才转换成 CAD；缺失时明确排除，不默认按 1:1。没有完整汇率的持仓快照不能作为完整账户净值。
- 分类必须有来源、日期和确认状态。敞口按已知汇率的持仓市值加权，未分类比例单列，账户现金不参与持仓行业/地区分类。基金穿透不会重复计入资产。

## CSV 导入

从“报告导入 → CSV 文件”下载模板，或查看 `public/samples/holdings.csv`。

最少需要 `security_name`（或 `ticker`）及 `market_value`。支持常见中英文列名，也可手动匹配。币种没有提供时必须在核对页确认，不能自动假设 CAD。

可选列：`type`, `units`, `price`, `currency`, `report_date`（YYYY-MM-DD）, `institution`, `account`, `sector`, `region`, `classification_source`, `classification_date`, `fx_rate`, `fx_date`, `fx_source`。

每次导入一个账户、一个日期的完整持仓快照。结构错列或混合账户/日期时会阻止确认，请先拆分或修正源文件。单次最多 10,000 行、文件最大 20 MB；建议个人使用时拆成较小文件。

## PDF 支持范围

使用 PDF.js 在浏览器本地提取文本和页码，不上传文件。当前只自动识别有限的结构化行：同一文本行包含名称、代码、类别、数量、单价、市值、币种七个独立文本单元。其余 PDF 会显示提取原文供对照，需手动补全持仓或使用 CSV；没有候选行时不能直接确认。

**尚未验证真实 iA Mobile / Wealthsimple 报表版式，不宣称通用解析支持。**扫描件 OCR、加密 PDF 密码输入和机构专用解析器暂未实现。要完善机构解析，需要脱敏样本。自动识别的账户、日期始终需要用户确认。

确认后仅保留提取及核对后的行、来源页/行、文件指纹与导入元数据，不保存原始文件。未确认的导入可取消；待核对记录可从最近导入继续，最后确认之前的编辑不保证自动保存。

## 隐私与保存

- 无后端、银行连接、AI 请求、分析追踪或金融凭证采集；不填写完整账号或卡号。
- 数据保存在当前站点来源的 `localStorage`，只在当前浏览器/浏览器配置中可用，**不自动同步、不加密**。共用同一浏览器配置的人可访问它；设备与浏览器应由本人保护。
- 清理浏览器数据、使用隐私窗口、换浏览器、换域名或端口都可能导致数据不可见或丢失。定期“导出备份”；导出的 JSON 含财务数据，应妥善保存。目前不提供 JSON 恢复界面。
- “清空数据”删除当前浏览器内此应用的账户、快照、导入和审计记录，不会删除已经下载到设备上的备份。
- 如以后改成服务器存储，必须另行实现私人登录、HTTPS 和受保护的存储；当前版本不是具备服务端身份验证的托管财务应用。不要把财务导出文件放进仓库或公开目录。

## GitHub Pages 发布

网站部署到 `Linda-YX/Linda-YX` 仓库的 `gh-pages` 分支，发布内容为编译后的静态文件，不包含用户浏览器保存的财务数据。

```sh
npm run deploy:pages
```

需要先提交当前源码，且当前 Git 身份有仓库推送权限。部署脚本以 `/Linda-YX/` 为资源路径前缀，正常推送 `gh-pages`，不强制覆盖分支历史。它不会自动修改 GitHub 仓库的 Pages 设置。

首次启用：打开仓库 **Settings → Pages**，在 **Build and deployment → Source** 选择 **Deploy from a branch**，将 **Branch** 设为 **gh-pages**、目录设为 **/(root)**，点击 **Save**。GitHub 部署成功后，该页面会显示真实网站地址及 **Visit site** 按钮。预期地址为 `https://linda-yx.github.io/Linda-YX/`；以 GitHub 显示的部署结果为准。

后续更新：提交代码，运行 `npm run deploy:pages`；GitHub 在 `gh-pages` 更新后重新部署。可在仓库 **Actions** 中查看 **pages build and deployment** 的状态。GitHub Pages 是公开演示网站，数据仍只保存在访问者自己的浏览器；目前打开默认展示虚构示例。不要将个人备份或真实报告提交到仓库。
